# Skyward Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Native Android + iPhone sun/moon dial app (port of the Kastro demo's narrow layout) plus an iPhone StandBy widget showing the dial.

**Architecture:** Kastro computes the sky; `:data` derives today's phase/light/moon spans (ported from the demo); `:dial` (pure Kotlin) turns a day into a renderer-agnostic `DialModel` and hit-tests taps. Compose Multiplatform draws the model in the app on both platforms; a SwiftUI `Canvas` draws the same model in the widget, fed by a Compose-free Kotlin framework from `:widget`.

**Tech Stack:** Kotlin Multiplatform, Compose Multiplatform, Kastro, Koin, Kermit, kotlinx-datetime, kotlinx-coroutines, kotlinx-collections-immutable, AndroidX ViewModel (KMP), DataStore Preferences (Android), WidgetKit/SwiftUI, XcodeGen.

**Spec:** `resources/docs/superpowers/specs/2026-11-21-skyward-design.md` — read it before starting any task.

**Demo source (reference for porting, GPL-3.0):** `https://github.com/yoxjames/kastro-demo`, clone it read-only outside the repo. Paths below like `demo:jsMain/.../sol/SolarPhaseState.kt` are relative to `src/` in that repo, package `dev/jamesyox/kastro/demo`.

## Global Constraints

- License GPL-3.0 (`LICENSE` at root, full text). Ported files keep a header crediting "Based on kastro-demo by James Yox (GPL-3.0)".
- Package root `app.skyward.<module>`. Bundle/application IDs and App Group name: builder's call, recorded in `gradle.properties` / `project.yml`.
- iOS deployment target 17.0. Android minSdk/targetSdk/compileSdk and JDK in `gradle.properties` (`skyward.minSdk=…` etc.), never in the version catalog.
- All dependency/plugin versions in `gradle/libs.versions.toml`, pinned to latest stable from live registry metadata via `scripts/latest-versions.sh`. No alpha/beta/rc.
- Libraries are exactly those in the spec's Libraries section. No HTTP, database, or navigation library.
- Non-UI modules (`:domain`, `:data`, `:dial`, `:widget`) declare `jvm()`; their tests live in `jvmTest` and run with `./gradlew :<module>:jvmTest`.
- Every module has a `README.md`; root `ARCHITECTURE.md` lists modules + mermaid graphs for Android and iOS (app and widget).
- Implementers load the `kotlin-preferences`, `jetpack-compose-preferences`, and `comment-preferences` skills before writing code.
- Logging via Kermit tagged `Logger`s. Collections in UiState/composable params are `ImmutableList`.
- Time range of a day: `date.atStartOfDayIn(tz) ..< date.plus(1, DateTimeUnit.DAY).atStartOfDayIn(tz)` (23/25 h on DST days).
- Location: approximate only. Android `ACCESS_COARSE_LOCATION` via platform `LocationManager` (no Play services). iOS when-in-use + `NSLocationDefaultAccuracyReduced = YES`. Usage string: "Skyward uses your approximate location to work out sun and moon times."
- Widget never requests location; reads the saved one. No-location copy: "Open Skyward to set location". Staleness is accepted, no age indicator.
- Git: work on branch `feat/skyward-app`; WIP commits per task with `[tag] Past-tense subject` messages, no AI attribution trailers; squash-merge locally into `main` at the end; never push.

## Review Focus

1. **Polar day / polar night** (e.g. Tromsø in June/December): no sunrise or sunset — dial must still draw a full ring, and the tabs must not crash on `first()` of an empty sequence. Test in Task 2.
2. **DST days** (Denver 2026-03-08 = 23 h, 2026-11-01 = 25 h): hour labels and spans must land on real clock times. Tests in Tasks 2 and 4.
3. **Midnight while open / widget timeline crossing midnight**: app must switch to the new day; widget entries after midnight must use the next day's data. Tests in Tasks 6 and 8.
4. **Days with no moonrise or no moonset**: moon ring still covers the whole day with one state. Test in Task 2.
5. **Location denied or never fixed**: app shows the "Location needed" state with a working action; widget shows the no-location copy. Tests in Tasks 6 and 8.
